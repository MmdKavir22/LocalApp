# Kavir PC Remote Launcher

گوشی اندروید ⇄ کامپیوتر ویندوز: بازی‌ها و برنامه‌های PC را از گوشی اجرا و ببندید. همه‌چیز لوکال است؛ گوشی برای کنترل به اینترنت نیاز ندارد (فقط هر دو باید به یک Wi-Fi وصل باشند).

```
android/   اپ اندروید (Kotlin + Jetpack Compose) + آپدیتر GitHub
server/    سرور ویندوز (Python / FastAPI) + پنل وب (server/web)
.github/   GitHub Actions: ساخت APK و انتشار در Releases
```

## ۱) راه‌اندازی سرور (ویندوز)

1. [Python 3.10+](https://www.python.org/downloads/) را نصب کنید (تیک *Add to PATH*). **محیط مجازی (venv) لازم نیست**؛ برنامه مستقیم با همین Python اجرا می‌شود.
2. پوشه‌ی `server` (یا فایل `KavirRemoteServer-*.zip` از Releases) را باز کنید و `start_server.bat` را اجرا کنید. وابستگی‌ها در اولین اجرا خودکار نصب می‌شوند (یا `install_dependencies.bat`).
3. در پنجره‌ی سرور آدرس‌ها نمایش داده می‌شود (فقط برای اتصال دستی لازم است).
4. پنل وب خودکار باز می‌شود: `http://localhost:8765`

> فایروال ویندوز: سرور (وقتی ادمین است) خودش قاعده‌ی ورودی برای TCP `8765` و UDP `8766` فقط از همان شبکه‌ی محلی (LocalSubnet) می‌سازد. اگر گوشی وصل نشد `diagnose.bat` را اجرا کنید. قبلاً: بار اول اجازه‌ی دسترسی Python روی **Private networks** را بدهید (پورت‌های TCP `8765` و UDP `8766` برای پیدا کردن خودکار).

اجرای خودکار با ویندوز (اختیاری): `install_autostart.bat` را **یک بار** اجرا کنید و تأیید UAC را بزنید، سپس ویندوز را ری‌استارت کنید. از آن به بعد سرور با هر ورود به ویندوز **با دسترسی Administrator** بالا می‌آید (بدون پرسش UAC)، و برنامه‌هایی که از گوشی اجرا می‌کنید هم با همین دسترسی اجرا می‌شوند. برای نصب با دسترسی عادی: `python run.py --install-autostart --no-admin`.
- با **Task Scheduler** ساخته می‌شود و با هر ورود به ویندوز سرور بدون پنجره اجرا می‌شود؛ `remove_autostart.bat` آن را حذف می‌کند.
- از اجرای هم‌زمان چند نمونه جلوگیری می‌شود (اجرای دوباره فقط پنل وب را باز می‌کند).
- اگر سرور Crash کند، خودکار دوباره اجرا می‌شود (نظارت داخلی + RestartOnFailure در Task Scheduler). لاگ: `%APPDATA%\KavirRemote\server.log`.
- وضعیت: `python run.py --autostart-status`. پورت دلخواه: `python run.py --port 9000`.

`start_server.bat` هم همیشه خودش دسترسی Administrator می‌خواهد (برای بستن برنامه‌هایی که با Administrator اجرا شده‌اند لازم است).

## ۲) اتصال گوشی

1. APK را از [Releases](../../releases) نصب کنید (نصب از منبع ناشناس را فعال کنید).
2. سرور روی PC روشن باشد و گوشی به **همان Wi-Fi** وصل باشد. اپ را باز کنید: کامپیوتر را خودش پیدا می‌کند و بدون IP و بدون کد وصل می‌شود.
3. اگر IP کامپیوتر عوض شود، اپ خودش دوباره پیدایش می‌کند. اگر Wi-Fi یا سرور قطع شود، هر ۳ ثانیه تلاش مجدد دارد.
4. **امنیت:** پیش‌فرض، هر گوشی روی شبکه‌ی خصوصی (192.168.x.x / 10.x / 172.16-31.x) می‌تواند وصل شود. در پنل وب ← «اتصال گوشی» می‌توانید «تأیید خودکار» را خاموش کنید تا هر گوشی جدید ابتدا روی PC تأیید شود، و هر دستگاه را قطع کنید.
5. اگر شبکه‌ی شما بین دستگاه‌ها جداسازی دارد (Client/AP Isolation، مثل Wi-Fi مهمان)، پیدا کردن خودکار کار نمی‌کند؛ «اتصال دستی» در اپ با IP و کد ۶ رقمی همچنان موجود است.

## ۳) استفاده

- **صفحه‌ی اصلی گوشی** فقط لیست برنامه‌هاست (نوارهای افقی کوچک با آیکون و نام). لمس هر نوار ← اجرای همان برنامه روی ویندوز.
- **تنظیمات ← برنامه‌ها**: افزودن، تغییر نام، آیکون، مسیر EXE، بکگراند، حذف و تغییر ترتیب (↑ ↓). همه‌چیز روی PC ذخیره و با پنل وب و بقیه‌ی گوشی‌ها هم‌گام می‌شود. اگر آیکون انتخاب نکنید، آیکون خود برنامه از ویندوز گرفته می‌شود.
- تب **در حال اجرا**: نام، PID، دکمه‌ی بستن (با تأیید) و Refresh.
- هر تغییر در پنل وب یا اپ، از طریق WebSocket فوراً در دیگری دیده می‌شود. داده‌ها در `%APPDATA%\KavirRemote` (دیتابیس SQLite، تصاویر و پوشه‌ی `backups`) ذخیره می‌شوند.

## ۴) امنیت

- همه‌ی درخواست‌ها نیاز به توکن دارند. توکن فقط از شبکه‌ی خصوصی و بدون کد (در حالت تأیید خودکار) یا با تأیید روی PC یا با کد ۶ رقمی (۵ تلاش اشتباه ← کد عوض می‌شود) صادر می‌شود.
- هیچ دستور دلخواهی اجرا نمی‌شود: فقط فایل‌های ثبت‌شده (`exe/bat/cmd/lnk`) و بدون shell.
- بستن فقط برای پردازش‌های برنامه‌های ثبت‌شده و فقط با `confirm`.
- حذف فقط با تأیید و قبل از آن بکاپ گرفته می‌شود (۱۰ بکاپ آخر + هر ۶ ساعت).
- سرور روی شبکه‌ی محلی HTTP ساده است؛ آن را به اینترنت Port-forward نکنید.
- محدودیت: اگر لانچر (مثل Steam) بازی را با پروسه‌ای دیگر اجرا کند و آن پروسه فرزند پروسه‌ی اجرا‌شده نباشد، ممکن است «در حال اجرا» نشان داده نشود.

## ۵) GitHub Actions و Releases

- با هر Push به `main` (تغییر در `android/` یا `server/`) یا اجرای دستی (**Actions ← Build & Release APK ← Run workflow**) APK ساخته، امضا و در Release با نسخه‌ی `v1.0.<شماره‌ی build>` منتشر می‌شود. زیپ سرور هم ضمیمه می‌شود.
- در صورت خطا، لاگ کامل در همان اجرا و گزارش build به‌عنوان Artifact ذخیره می‌شود.
- **امضا:** secretهای `KEYSTORE_BASE64`، `KEYSTORE_PASSWORD`، `KEY_ALIAS`، `KEY_PASSWORD` لازم‌اند تا همه‌ی نسخه‌ها با یک کلید امضا شوند (بدون آن آپدیت روی نسخه‌ی قبلی نصب نمی‌شود). کلید هرگز در Git نیست.

## ۶) آپدیت داخل اپ

تنظیمات ← **GitHub Update**: آدرس ریپو (و برای ریپوی خصوصی، Personal Access Token با دسترسی خواندن *Contents*) ← **Check for Updates** ← **Update**. اپ آخرین Release را با نسخه‌ی نصب‌شده مقایسه می‌کند، APK را دانلود می‌کند و نصب‌کننده‌ی اندروید با تأیید شما باز می‌شود. توکن رمزنگاری‌شده ذخیره می‌شود و فقط به `api.github.com` فرستاده می‌شود.

## توسعه

```
cd server && pip install -r requirements.txt && python run.py   # بدون venv
cd android && gradle assembleDebug        # نیاز به Android SDK
```
